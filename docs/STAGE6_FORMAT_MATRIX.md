## What independent acceptance actually checked

1. The fixture PDFs were generated by **pypdf** (`PdfWriter`) with ordered, different page dimensions (one-page `96×72 pt`; three-page `96×72`, `72×96`, `120×84 pt`). RightConvert/PDFium did not generate these input PDFs. PDF input page counts were cross-checked by **pypdf** and independently rasterized by **PyMuPDF** before conversion.
2. For each PDF → PNG/JPG/WebP route, **Pillow** opened and decoded the resulting pixels, checked the exact format, image/page count, and dimensions at the 144 DPI output scale. For TIFF, Pillow iterated and decoded **all** frames in order. For the page ZIP, Python `zipfile` checked the archive CRCs and exact ordered `page-0001.png` etc. entries, then Pillow decoded **every** PNG page. The engine's actual ZIP publication name is `<source>-pages.zip` (or `-pages (1).zip` on collision).
3. Image → PDF and ordered-image-merge results were parsed with **pypdf** to verify page counts and page sizes, and separately rasterized with **PyMuPDF** to confirm each page can render. The ordered merge uses distinguishable dimensions in all three source images and checks the output page order.
4. Six **native Office ZIP packages** containing visible safe text, cells and slide content were generated by the independent `tests/test_office_provider.py::_native_source` fixture generator, recognized by the engine's strict content inspector, then passed to the real `engine.convert_file(..., office_path=absolute_soffice)` API. **All six produced PDFs were independently page-counted with pypdf and raster-rendered by PyMuPDF**. No native Office PASS is inferred from a mock, metadata inspection or LibreOffice's command exit alone.
5. Every conversion was run with a pre-existing output-name collision sentinel. It must publish the next available output name, preserve sentinel contents byte for byte, leave **SHA-256 of all source files unchanged**, and remove conversion staging directories. Each output was checked after real conversion, not inferred from `supported_targets()` alone. The disposable `.rc-stage6-*` root was absent after completion.
6. The previously accepted 16 source families are regenerated using the Stage 5 fixture generators (including local audio/video files from FFmpeg), and their 57 legacy route advertisements are compared to the actual previous 57-route PASS evidence. Changed, missing, or additional legacy routes make this validator fail.

The standard PATH and Program Files discovery did not find a system-installed LibreOffice. Subsequently, the official **LibreOffice 26.8.1.1 x64 MSI** was extracted under `build/stage6/libreoffice-isolated/portable-root/` for **QA only**; its real `program/soffice.com` binary was supplied by absolute path to the live engine. It was not installed into Windows or bundled into a customer release. **6/6 Office formats were natively converted and decoded**, with source SHA, preserved collision sentinel and clean staging verified for each. Native Office support remains conditional on a compatible external LibreOffice runtime being present/configured for the paying customer.

The validator automatically generates six independent, passive Office fixtures named `stage6.docx`, `stage6.xlsx`, `stage6.pptx`, `stage6.odt`, `stage6.ods`, and `stage6.odp` when a real LibreOffice executable is configured. The `--office-fixtures` option also accepts a supplied directory of real test files. Every presented document must pass strict inspection before the engine executes native conversion. A missing, rejected or unconverted Office file is explicitly reported as unverified/failed, never counted as a native PASS.

## Reproduction

Run from `D:\fuckpdf` in PowerShell, with the locally installed Python environment providing Pillow, pypdf, PyMuPDF, pypdfium2, pytest and FFmpeg/FFprobe:

```powershell
python scripts/validate_stage6.py --report "$env:TEMP\rightconvert-stage6-validation.json"
python -m pytest -q tests/test_stage6_matrix.py
```

Reproduce the **full real Office** acceptance using the isolated QA executable (if still available in this workspace):

```powershell
python scripts/validate_stage6.py --libreoffice "D:\fuckpdf\build\stage6\libreoffice-isolated\portable-root\program\soffice.com" --report docs/STAGE6_FORMAT_MATRIX_RESULTS.json
```

Without `--report`, the script writes no persistent JSON. With `--report`, its JSON records each route, live detected targets, independent decoder result, source integrity, preserved collision and staging cleanliness, and Office native PASS/UNVERIFIED/FAIL statuses. It exits nonzero if any advertised conversion executed on the installed backend fails. The attached JSON records **19/19 Stage 6 operations PASS, 6/6 Office PASS, 0 failures, and 57/57 historical advertisements unchanged**. All test documents are small, synthetic/local; extreme sizes, all color modes, exotic PDF constructs, complex Office formatting fidelity, Windows installer behavior and Explorer UI are outside this test's evidence.
